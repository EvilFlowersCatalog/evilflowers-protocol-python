# EvilFlowers Protocol Python Client

A typed client for the [EvilFlowers Catalog](https://github.com/EvilFlowersCatalog/EvilFlowersCatalog)
REST API, plus Pydantic models generated from the OpenAPI spec in
[`evilflowers-protocol`](https://github.com/EvilFlowersCatalog/evilflowers-protocol).

The package is layered so the data layer follows the OpenAPI spec automatically:

| Layer | Module | Changes when |
| --- | --- | --- |
| Data (generated) | `evilflowers_protocol.schema` | the spec changes; regenerated by CI, never hand-edited |
| Overlay | `evilflowers_protocol.forms` | upstream fixes a generator bug (a test says which override to delete) |
| Transport | `evilflowers_protocol.transport` | almost never: auth, retries, envelopes, pagination, multipart over stdlib `urllib` |
| Endpoints | `evilflowers_protocol.client` | an endpoint is added or moved |

`forms.py` subclasses the generated request forms (`EntryForm`, `AuthorForm`, …) and
overrides only the fields the catalog's spec generator gets wrong. Each override is marked
`# upstream:`. Response models are small projections of the generated serializers.
`tests/test_overlay.py` fails when a regeneration fixes an override or drifts from a
projection.

Requires Python 3.12 or newer. The only runtime dependencies are `pydantic` and `pydantic2md`.

## Install

The package is not on PyPI. Install it from git, pinned to a commit:

```bash
pip install "git+https://github.com/EvilFlowersCatalog/evilflowers-protocol-python@<commit>"
```

With Poetry:

```toml
[tool.poetry.dependencies]
evilflowers-protocol = { git = "https://github.com/EvilFlowersCatalog/evilflowers-protocol-python.git", rev = "<commit>" }
```

## Usage

The token is a JWT: either an access token from `POST /api/v1/token`, or an API key from
`POST /api/v1/api_keys`, which does not expire and suits batch jobs.

```python
import logging
from pathlib import Path

from evilflowers_protocol.client import CatalogClient, Conflict
from evilflowers_protocol.forms import AuthorRef, EntryConfig, EntryCreate, image_data_uri

logging.basicConfig(level=logging.DEBUG)  # optional: one line per request

client = CatalogClient("https://dev.evilflowers.elvira.stuba.sk/api/v1", token="<api key>")
client.ping()  # fails fast on a bad URL or token

catalog = client.resolve_catalog("digitized-books")  # exact url_name, or a UUID

entry = EntryCreate(
    title="Dejiny Slovenska",
    language_code="sk",
    authors=[AuthorRef(name="Ján", surname="Novák")],
    identifiers={"isbn": "9788022345678"},
    published_at="1998",
    config=EntryConfig(evilflowers_ocr_enabled=False),
    image=image_data_uri(Path("cover.jpg")),  # the cover travels inside the entry
)

try:
    created = client.create_entry(catalog.id, entry)
except Conflict as exc:
    # 409: the catalog already has an entry with this title, ISBN or DOI.
    print("duplicate:", exc.body)
    matches = client.find_entries(catalog.id, title=entry.title)
    if not matches:
        raise  # the clash was on ISBN or DOI, not on title
    created = matches[0]

existing = client.get_entry(catalog.id, created.id)
if not any(a.mime == "application/pdf" for a in existing.acquisitions):
    client.upload_acquisition(catalog.id, created.id, Path("book.pdf"))  # streamed from disk
```

### Behaviour

- **Errors.** Every failure raises `CatalogError`, which carries `status`, `body` (the parsed
  JSON problem detail), `method` and `url`. Its subclasses are `Unauthorized` (401/403),
  `NotFound` (404) and `Conflict` (409).
- **Retries.** Connection errors, timeouts and 502/503/504 are retried `retries` times
  (default 3), with exponential backoff and jitter. Other statuses are not retried.
  If the server finished a `POST` before a gateway error, the retry repeats it: a duplicate
  entry comes back as `Conflict`, but a duplicate upload attaches the file twice. Check
  `get_entry(...).acquisitions` before uploading again, as above.
- **Redirects** are not followed, because that would send the token to another host. A
  3xx usually means `base_url` is wrong.
- **Updates.** The backend still requires `title` and `language_code` on every `PUT`, so set
  both on `EntryUpdate`.
- **Threads.** One client can be shared across a process's threads.
- **Unwrapped endpoints.** `client.transport.get(path, Model)`, `.send(...)`, `.iter_pages(...)`
  and `.upload(...)` reach any other endpoint with the same auth, retries and errors.
- **Logging.** Through the `evilflowers_protocol` logger, at DEBUG only. The token is never
  logged and never appears in `repr()` or in exception messages.

## Development

```bash
poetry install
poetry run pytest
poetry run ruff check
poetry run mypy
```

The tests run against a stdlib `http.server` fake on localhost; no catalog instance is needed.

## Automated OpenAPI sync

The spec flows through three repositories, keeping the branch or tag name at every hop:

1. **EvilFlowersCatalog** `docs.yml` runs on every push. It generates the spec with
   `manage.py openapi` and commits it to the branch of the same name in `evilflowers-protocol`.
2. **evilflowers-protocol** `dispatch-python-client.yml` runs on that push and sends a
   `repository_dispatch` (`protocol-updated`, payload `{"ref": ...}`) here.
3. **This repo** `generate-client.yml` checks out the branch with the same name, creating it
   from the default branch if needed. It fetches `openapi/openapi.yaml` at that ref, runs
   datamodel-codegen, and then checks the client against the result: the package must import
   and `pytest` must pass.
   - Checks pass: the commit is pushed to the branch.
   - Checks fail: the commit goes to `schema-sync/<ref>` and a pull request into the branch is
     opened (or commented on, if one is already open) with the failures. Most failures come from
     `tests/test_overlay.py` and name the `forms.py` override to change. Fix it on that PR.

You can also run the workflow by hand with a `ref` input (default `develop`), for example to
repair a branch.

To regenerate locally, with the same generator version and options as CI:

```bash
poetry run datamodel-codegen   # reads [tool.datamodel-codegen] in pyproject.toml
poetry run pytest
```

`schema.py`, `openapi/openapi.yaml` and `VERSION.txt` are generated. Do not edit them by
hand; fix type problems in the catalog's spec generator (`EvilFlowersCatalog/apps/openapi/`)
instead.
